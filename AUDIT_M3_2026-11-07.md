## Findings

1. **[High] server.js — drafts were in-memory only; a restart lost them.**
   Evidence: after the server died between 12:35 and 13:22 EAT, GET
   /api/invoices/INV2-8ACF-6WEJ-L9R3-ULHK/reminders returned drafts 0 while
   sent 1 (the log file persisted, the drafts did not). A draft made before a
   restart could not be approved after it (404). FIXED: drafts now persist in
   reminders_drafts.json, loaded at startup. Verified live: draft created,
   server killed and restarted, same draftId approved -> status sent.
2. **[High] No git repo in ~/workspace/paypal-hackathon.**
   Evidence: `git status` -> "fatal: not a git repository"; find shows no
   .git under the project. None of today's code is committed or pushed to
   github.com/1RagaZ/invoicepilot. This does not make the M3 code wrong; it
   blocks Milestone 4, because Render deploys from that repo. FIXED 2026-11-07
   ~13:45 EAT: Jackson authorized the GitHub login in the browser himself;
   `gh auth login` completed as 1RagaZ; the M3 commit 7673b62 was pushed to
   origin main (verified: remote HEAD is 7673b62). The credential helper was
   missing after login and was set explicitly
   (`git config --global credential.helper "!/usr/bin/gh auth git-credential"`).
   The repo now holds the finished M1-M3 code.
3. **[Medium] public/index.html exposes no reminder flow.**
   Evidence: 87 lines, only /api/parse, POST /api/invoices, GET status. The
   draft/approve loop is API-only, so the demo video cannot show it in the
   browser until UI is added. FIXED 2026-11-07 ~13:50 EAT: the page was
   rebuilt as a designed product page (brand header, 4-step loop strip, cards
   per step, status pills, draft cards with AI/template source badges,
   reminder history). The old page was the generic centred-column form that
   reads as AI-made. JS extracted and node --check clean; served page verified
   live; all tests still green.
4. **[Medium] No auth on any /api route.**
   Evidence: server.js has no auth middleware. A public demo URL would let
   anyone create/send sandbox invoices and reminders. Bounded: sandbox only,
   no real money. OPEN — state it before the URL goes public.
5. **[Medium] Draft endpoint swallowed all AI errors silently.**
   Evidence (before fix): the try/catch around draftReminder fell back to the
   template with no log, so a config failure looked exactly like a model
   outage. FIXED: the error is now logged server-side. Verified live:
   "AI draft failed for INV2-8ACF-6WEJ-L9R3-ULHK: AI request failed: 503".
6. **[Low] Create endpoint passes dueDate through without format validation.**
   An invalid date reaches PayPal, which rejects it with a 400. Confusing
   error message only. OPEN.
7. **[Low] reminders_log.json uses appendFileSync.**
   Concurrent sends could interleave lines; single-threaded Node, small
   writes, low risk. OPEN.
8. **[Low, known limit] checkOverdue returns 'unconfirmed_status' for
   PARTIALLY_PAID and other non-SENT statuses.**
   A partially-paid invoice past its due date is genuinely overdue in the real
   world and would be missed. The spec deliberately limited the rule to SENT
   until the full status list is confirmed from sandbox data. OPEN — real-merchant
   follow-up, not a demo blocker.
9. **[Medium] Draft endpoint hung past 100s when Gemini stalled.**
   Found live 2026-11-07 ~13:40 EAT: a draft call never returned while the
   model hung (no timeout on the model call). FIXED: callModel now aborts
   after 30s and the endpoint falls back to the template. Verified live: a
   full draft + approve + list cycle completes in ~6s. Tests still green.
